# 踩雷清單（實戰紀錄）

依發生階段排列。每一條都真的發生過。

## 登入與環境

- **帳密檔不只一份**：`~/.aigo/.env`、工作區 `.aigo/.env`、`~/.aigo-transfer/.env` 可能指向不同帳號或過期密碼（實測 `~/.aigo/.env` 回 401、工作區那份才對）；登入失敗先確認 `env_file` 指的是哪一份。
- **從子目錄執行登錄腳本會登入錯租戶**（demo 與正式共用 auth，照樣回 201）：確認截圖畫面的租戶名稱。
- puppeteer-core 找不到：在 skill 目錄 `npm install`，或工作目錄自己裝。

## 截圖

- **PopMenu 用程式點擊會跑到左上角**：選單位置取自 `event.clientX/Y`，程式 `el.click()` 是 0。用 `mouseClick`。
- **選單和觸發按鈕取聯集**會夾到中間不相關的畫面；只取選單第一項與最後一項。
- **視窗截整頁**縮進頁面後看不清；截 `.modal` 本身。
- **內層捲動沒歸位**：測試對話截到一半的回覆。截圖前設好 `scrollTop`。
- **點開對話會把未讀歸零**：拍前備份、拍後還原；還原時如果截圖期間真的有新訊息，數字會對不上，屬正常。
- **示範資料是空的**：面板顯示「尚未建立」沒有教學價值；用 app 的 action 預填，或送一則測試訊息讓系統自己產生。
- **送測試訊息會真的推到 LINE**：只對自己的測試帳號做。
- **模式切換拍完要切回**，而且要確認切回成功（在計畫裡檢查原本的按鈕還在不在）。
- **截了真實終端**：帶進 agent 的 UI、本機路徑、token，字還糊。指令一律用 `Deck.term()` 渲染。
- **桌面截圖入鏡了通知或其他客戶的視窗**：拍前關通知、收視窗；拍後看工作列與系統匣。
- **`--title` 找不到視窗**：標題會隨語系、分頁、檔名變（例：「設定」vs「Settings」、Chrome 標題是分頁名）。先 `desktop_shot.py --list` 看實際標題，取穩定的子字串。
- **DPI 縮放讓座標差 1.5 倍**：`desktop_shot.py` 已宣告 DPI aware，`--region`／`--mark` 都用實體像素；別拿其他工具印的邏輯座標來填。
- **`s.desktop()` 之後 shots.json 少了桌面那幾筆**：lib.mjs 在記憶體裡累積 manifest，`desktop()` 已經會重讀合併；自己另外寫 shots.json 的話也要先讀再寫。

## 截圖時抓到的產品 bug（截圖就是 UI 驗收）

- 面板永遠顯示「尚無記憶紀錄」：前端共用呼叫函式已經拆掉 `{status, result}` 信封，元件又讀一次 `.result`。後端測試全過，只有畫面看得出來。
- 清單欄位顯示 `['…']`：後端把 list `str()` 成字串存起來。
- 區塊只有標題沒有內容：條件只處理了有明細的情況。

這類修正要照 app 的發布規則上線（發布 → PR → merge），並記進 app 的評估紀錄；修完重拍。
動手前先過 `workflow.md` P4 的確認清單——下面三種都被誤當成 bug 過：

- **簽核攔截**：預設表的寫入回 `approval_status: pending`，畫面顯示「待簽核」。是租戶簽核規則，不是錯。
- **空資料**：面板「尚未建立」是因為示範資料沒預填，不是前端壞掉。
- **程式點擊**：選單跑到左上角是 `el.click()` 沒有座標，是截圖方式的問題。

## 內容

- **探勘讀過的設計脈絡會滲進手冊**：讀完原始碼與 CHANGELOG 後，分隔頁、參數頁的導言很容易寫出「這個功能是為了…而設計」「v12 起改成…」「後端會先…再…」。讀者只需要「是什麼、在哪、怎麼操作、改了會怎樣」；寫完用刪除測試掃一遍（`writing-guide.md`「不插播」）。
- **截圖時修的 bug 被寫進手冊**：那是製作過程，放交付對話，不放手冊。

- **前端說明文字可能過時**：例如開關的 hint 說「關閉時仍可…」，實際後端兩個開關效果一樣。以後端程式為準。
- **「目前值」憑印象寫會錯**：一律從設定 API 讀，附錄用程式產生。
- **沒查證的推論會混進去**：例如「旅程在客人婉拒後不打擾」——程式裡沒有就刪。
- **沒選測試報告就放數據**：開發歷程有數據不代表客戶想看；Phase 0 選了測試報告才放（`acceptance()` 會擋）。
- **測試數據被「美化」**：98.16% 寫成 98.2% 可以，寫成「近 99%」不行；挑最好看的那一次、拿掉分母、
  把開發中途的舊數字當結果，都是錯的。照最新一次的來源原文抄。
- **把工程測試當交付品質**：「128 項單元測試全數通過」「覆蓋率 92%」不是測試報告要的數據，讀者無法據此判斷能不能信任結果。
- **為了報告另外跑測試**：臨時跑的數字沒經過驗收流程，不放。只呈現開發歷程已有的數據；找不到就請使用者提供或拿掉測試報告。
- **功能展示寫成操作說明**：展示頁出現「按這裡 → 再按那裡」就是寫錯了；只講這個功能能幫你做什麼。
- **功能展示寫成廣告**：「智慧」「大幅提升」「業界領先」都不寫；寫它做什麼、會怎樣。
- **把事實寫進人設**：手冊要教使用者「規定放知識庫、語氣放人設」，自己寫範例時也要遵守。
- 範例和截圖用真實客戶的品牌或人名時，確認這份文件的讀者可以看；要對外的版本先去識別。

## 排版

- **封面標題孤字斷行**（「操作手」＋「冊」）：`white-space: nowrap` 或縮字級。
- **提示框在直欄裡被撐成一大塊**：`.note` 預設 `flex: none`，只有在橫排 `.row` 裡才 `flex: 1`。
- **兩張並排圖超出右緣**：內容區只有 1392，兩張各 ≤ 680。
- **封面主畫面被右緣切掉**：寬度 ≤ 720。
- **版面檢查器的假陽性**：封面、分隔頁、頁尾不在 `.content` 內，不要算。
- **擠壓重疊**：內容總高超過內容區時，flex 會把上方的 `.row` 壓扁，截圖和下方表格重疊——下緣檢查抓不到。`render.mjs` 會檢查 `scrollHeight > clientHeight`；修法是給上方圖片加 `maxh`。
- **全頁截圖包瀏覽器框後多 26px**：原本剛好塞滿的頁會溢出，全景圖寬度從 1040 降到 960～1000。
- 左欄兩張圖疊太高、圖說壓到頁尾：第二張移到右欄底部。
- **手刻目錄頁**：頁序一改頁碼就錯。目錄一律交給 `Deck.write()`；分隔頁的頁目也省略 `items` 讓它自動列。
- **頁標題寫成一句話**：目錄列會被截成「…」。標題寫成名詞片語，說明放導言。
- **開始之前的頁排在 PART A 分隔頁後面**：會被目錄歸進 PART A。前置頁放在第一個分隔頁之前。

## 交付

- PDF 十幾 MB，不要預設進程式碼 repo。
- **dsf 2 的全頁截圖是 3200×1800 PNG**：Chrome 無損內嵌，40 頁輕易超過 20 MB。`render.mjs` 會自動壓縮；
  畫面是照片、圖表、漸層多的 app 最容易壓不下來。
- **把 `disc/…original.pdf` 當成品寄出**：那是壓縮前的原檔，只當備份。
- **用網路圖片省事**（`<img src="https://…">`）：寄出去的 PDF 雖然會內嵌，但渲染當下抓不到就缺圖，
  而且來源不受控。`render.mjs` 直接擋掉；下載成本機檔案放進 `shots/`。
- **壓不下來就自己決定超標交付**：要先問使用者（`workflow.md` P7）。
- 還原資料狀態後用 `prep_state.py diff` 再確認一次。

## 用途

- **沒問用途就開工**：「幫我做份手冊」也要先走 Phase 0，使用者可能還要測試報告、功能展示或整合測試；只做選了的。
- **Phase 0 塞成一題五個選項**：AskUserQuestion 每題最多 4 個選項；照 `prompts.md` §0 拆成「PDF 文件」＋「進度報告」兩題。
- **把進度報告做成 PDF**：進度報告是文字訊息（可附圖），用 `progress.py`；`Deck(purposes=…)` 放進度報告會報錯。

## 整合測試

- **把整合測試和測試報告搞混**：測試報告只整理既有數據、不跑；整合測試是這次實際跑。使用者要「找 bug、全部點一遍」選的是整合測試。
- **沒核准計畫就開跑**：端到端會建立、刪除資料，巡檢會點開對話（未讀歸零）。先 `--list` 提計畫（GT1）、備份狀態再跑。
- **只看自動判定**：腳本抓得到 JS 例外、API 錯、`undefined`，抓不到「成功提示說已建立但列表沒有」「錯誤訊息看不懂」。
  通過的也要掃總表；自動判通過但不合理的改判疑慮（GT2）。
- **假問題寫進報告**：測試帳號沒權限的 403、簽核 `pending`、冷啟動 503、示範資料沒預填的空狀態——照 P4 確認清單排除。
- **預期中的錯誤被當疑慮**：表單驗證案例的「請輸入名稱」要用 `c.expectText()`（自動放行）；預期的 422 用 `allowStatus`。
- **巡檢在正式站點到會改資料的按鈕**：`DANGER` 清單沒涵蓋的字（例：「完成」「同意」）用 `itest.sweep_skip` 或 `t.sweep({ skip })` 補；
  開關、勾選本來就不點。不確定就不要在正式站跑巡檢。
- **跑到一半修 bug**：報告要反映測的當下；整份跑完、交付後再問要不要修，修完重跑標「修正後重測通過」。
- **重跑後沿用舊判讀**：`review.json` 的 `run` 對不上就是過期，要重看截圖（`d.itest()` 會擋）。
- **測試資料沒清**：用固定前綴（`IT-YYYYMMDD`），跑完刪掉並 `prep_state.py diff` 確認。

## 進度報告

- **只回「做好了」**：客戶不知道去哪裡看、驗什麼、何時回覆，又要有人轉述。一律跑 `progress.py` 產訊息。
- **用 `--allow` 放行內部用語**：`allow` 只給客戶自己會講的詞（品牌、平台名）；「API」「部署」這類要改寫成白話。
- **步驟沒自己走過就發**：對方第一步就卡住，這則訊息就白發了。發之前自己照步驟走一遍。
- **給開發者預覽頁的網址**：對方打不開。`url` 一律問使用者要交付站的連結。
- **從客戶資料猜對方有沒有 AI**：不讀客戶資料，每次問使用者（`with_ai`）。
- **一件事發一則**：一週一則、涵蓋整週，週會前 48 小時交；拆成好幾則對方會漏看。
- **把整本操作手冊當週報**：每週只發進度報告，整本手冊留到最後交付。
- **附圖沒檢查就送**：附圖跟手冊截圖一樣要過 G2（密碼、金鑰、客人個資）；`progress.py` 有附圖時會提醒。
- **附圖塞太多**：只在文字講不清楚時補（例：新按鈕在哪）；每件事 1～2 張就夠。
