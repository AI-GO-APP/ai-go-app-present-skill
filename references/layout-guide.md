# 版面規格

## 畫布

| 項目 | 值 |
|---|---|
| 頁面 | 1600×900 px（16:9），PDF 每頁同尺寸 |
| 邊距 | 左右 60、上 44、下 54（頁尾在下方 20） |
| 標題區 | kicker（部分名）15px、標題 36px 粗黑、導言 19px 灰，約佔 120px |
| **內容區** | **約 1480×680** —— 所有圖與表要塞進這裡 |
| 字型 | Noto Sans TC（Google Fonts，退回微軟正黑體） |

## 圖片尺寸建議

| 版型 | 圖寬 |
|---|---|
| 全景圖解＋右側編號說明 | 1000～1040 |
| 左圖右表 | 圖 560～640，表佔其餘 |
| 兩張並排 | 每張 ≤ 722 |
| 三欄小圖（側欄面板） | 每張 220～260 |
| 細長圖（收件匣欄、手機畫面） | 高 ≤ 560～620，單獨一欄 |
| 封面斜放主畫面 | 740 |

`Deck.shot(name, maxw, maxh)` 會等比縮到兩個上限都滿足。

## 字級

| 元素 | 大小 |
|---|---|
| 內文、步驟 | 16～17 |
| 表格（compact／dense） | 15／14.5 |
| 圖說 | 14 |
| 編號圓點 | 28px 圓、15 字 |

1600 寬的頁面在螢幕上 100% 顯示時，15px 約等於一般文件 11pt。低於 14 不要用。

## 顏色

- `--brand`：部分名、步驟編號、分隔頁色條。依 app 的品牌色設（`Deck(brand="#…")`）
- **圖解編號用藍色（#2563EB）**：跟多數 app 的品牌橘／紅明顯區隔，不會被誤認成介面元素
- chip：ok 綠、warn 橘、info 藍、danger 紅、預設灰 —— 盡量對應 app 畫面上相同意義的顏色

## 檢查表（G4）

總表先看一輪，再開有疑慮的單頁：

- [ ] 沒有東西壓到頁尾或超出右緣（`render.mjs` 會列，但只看 `.content` 內）
- [ ] 圖說沒有和頁尾重疊
- [ ] 標題沒有孤字斷行（封面標題特別注意，用 `white-space: nowrap` 或縮字級）
- [ ] 提示框（note）沒有被撐成一大塊空白（直欄容器裡 note 要 `flex: none`）
- [ ] 截圖縮太小看不清的 → 換局部截圖或拆頁
- [ ] 同頁兩張圖高度差太多時，改成上下或單欄
- [ ] 每一部分的頁數大致符合大綱的比重

## 常見修法

| 問題 | 修法 |
|---|---|
| 右欄內容太多往下溢出 | 表格改 `dense`、刪一列、把圖改小，或拆成兩頁 |
| 左欄兩張圖疊起來太高 | 把第二張移到右欄底部，旁邊放圖說 |
| 視窗截圖太小 | 改截 `.modal` 本身，不要截整頁 |
| 頁面下半部大片空白 | 放大截圖、控制點地圖加 `min-height`、或把相關內容併進來 |
